**Report Quality-Control Checklist**

Reviewer checklist for commercialisation reports

Version 0.1 | 05/06/2026 | For internal pilot use

# 1\. Purpose

This checklist standardises review of agent-generated Innovation Commercialisation Exploration Reports before they are relied upon or shared.

# 2\. Checklist

| **Area**                 | **Check**                                                                            | **Pass / Partial / Fail** | **Reviewer notes** |
| ------------------------ | ------------------------------------------------------------------------------------ | ------------------------- | ------------------ |
| Structure                | Report follows the approved template and includes all required sections.             |                           |                    |
| Confidentiality          | Confidential information is protected and search terms are non-confidential.         |                           |                    |
| Extraction               | Disclosure data is accurately extracted and missing information is flagged.          |                           |                    |
| Sources                  | Factual claims include source notes or are marked as assumptions.                    |                           |                    |
| Market analysis          | Market applications are relevant and ranked with rationale.                          |                           |                    |
| Prior art                | Patent/publication/product landscape is sourced and caveated.                        |                           |                    |
| Company matching         | Company recommendations are evidence-based and scored.                               |                           |                    |
| Contacts                 | Named contacts are public/sourceable or role-based; compliance notes included.       |                           |                    |
| Figures/tables           | Tables and figures are complete, useful and assumption-labelled.                     |                           |                    |
| IP/legal                 | Issues are flagged for review and not presented as legal advice.                     |                           |                    |
| Software/data            | Open-source, datasets, AI-generated code and duplicability addressed where relevant. |                           |                    |
| Physical product/process | Manufacturing, validation, scale-up and regulation addressed where relevant.         |                           |                    |
| Outreach                 | Drafts are non-confidential and include appropriate call-to-action.                  |                           |                    |
| Next actions             | Actions are prioritised, practical and owner-ready.                                  |                           |                    |

# 3\. Approval recommendation

| **Decision**             | **When to use**                                                                |
| ------------------------ | ------------------------------------------------------------------------------ |
| Approve for internal use | Minor issues only; no confidentiality/source concerns.                         |
| Approve with amendments  | Useful report but needs limited edits.                                         |
| Return for rework        | Material evidence, source, confidentiality or quality gaps.                    |
| Escalate                 | Potential urgent IP, legal, publication, data protection or reputational risk. |
